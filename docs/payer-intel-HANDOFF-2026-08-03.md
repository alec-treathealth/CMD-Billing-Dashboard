## 1. What this feature is

Monthly LLM research pipeline that tracks payer + federal behavioural-health /
SUD billing policy changes and lands them as dated, citation-backed findings for
Qualify RAG retrieval.

- **Non-PHI throughout.** Every row comes from a public payer bulletin, CMS fact
  sheet, Federal Register document, or standards-body page. Nothing is patient-,
  member-, or claim-derived, and nothing joins to a PHI table.
- **Tenant-agnostic.** Industry reference intelligence, so **no
  `business_entity_id`** anywhere.
- Nine research keys, one API invocation per key.

## 3. Hard-won API facts — do not re-derive these, they cost live probes

All verified against the live API on 2026-08-03, not from memory.

- **`web_search_20260318`** and **`web_fetch_20260318`** are the correct tool
  versions. `web_search_20260318` adds `response_inclusion`.
- **Do NOT declare `code_execution`.** Dynamic filtering auto-provisions it;
  `allowed_callers` defaults to `["code_execution_20260120"]` on `_20260209`+.
- **`response_inclusion: "full"` is mandatory, not a preference.** `"excluded"`
  removes the `web_search_tool_result` blocks that carry the retrieved-URL set,
  and that set *is* the provenance gate.
- **THREE stop reasons, not two:** `end_turn`, `pause_turn` (resend unchanged),
  `tool_use`. Because `emit_findings` is a *client* tool and web_search is a
  *server* tool, the API returns `tool_use` and defers the search when both land
  in one parallel group. **Every healthy run is multi-turn.** A healthy turn 1
  ends on `tool_use`.
- **Assistant content must be echoed back BYTE-IDENTICAL** — the same parsed
  array, never filtered or rebuilt. Thinking blocks (Opus 5 emits them
  unrequested), `server_tool_use` blocks, and `encrypted_content` must round-trip
  exactly or the resend 400s.
- **`container` is REQUIRED to continue.** Without reattaching via the top-level
  `container` param (bare string from `response.container.id`), turn 2 returns
  `400 "container_id is required when there are pending tool uses generated by
  code execution with tools."` This happens **even though we never declare
  code_execution**.
- **Search/fetch errors return HTTP 200.** `content` is a single error **OBJECT**
  on error vs a **LIST** on success — branch on `Array.isArray(block.content)`.
  Under dynamic filtering those error blocks **may never surface at all** (nested
  results come back as `encrypted_code_execution_result`), so **run health must
  not depend on seeing them**.
- **Strict tool use + web_search is fine.** The documented citations/structured-
  outputs 400 is scoped to `output_config.format` plus citations on *user-provided*
  `document`/`search_result` blocks. Probed clean.
- **No `citations` array appears on text blocks** under dynamic filtering. That is
  why provenance is validated against the retrieved-URL set rather than citations.
- **`usage.server_tool_use.web_search_requests` / `.web_fetch_requests`** are real
  and populated. Also present: `output_tokens_details.thinking_tokens`,
  `service_tier`, `inference_geo`.
- **`undici`/`fetch` cannot be used.** A research turn exceeds undici's 300s
  headers timeout (`UND_ERR_HEADERS_TIMEOUT`) and `undici` is not resolvable in
  this repo to override the dispatcher. Use `node:https`. **Do not switch to
  streaming** — reassembling content blocks from SSE deltas jeopardises the
  byte-identical echo that `pause_turn` requires.
- **`max_content_tokens` bounds text but NOT PDFs** (documented). So `fetchUses` is
  the only real cost ceiling, and PDFs are what drove input tokens from 2.2M to
  6.4M.
- **`allowed_domains` IS NOT STRICTLY HONORED.** See §6.

## 5. Failure gates — semantics and why each exists

Implemented in `src/intel/payer_policy/client.ts`. A FAILED run must not persist
findings; a gate tripping means the payload cannot be trusted.

| gate | condition | why |
|---|---|---|
| TRANSPORT | non-200 | recorded, not thrown, so a FAILED run row can still be written |
| TURN BUDGET | 12 turns | prevents an infinite `pause_turn` loop |
| **A** | `emit_findings` never called | **`end_turn` without it is FAILED, not "no findings"** — the highest-priority correctness rule; a well-formed response that silently means nothing happened is the bug this whole design refuses |
| **B** | `web_search_requests === 0` | nothing researched; also the only reliable all-errored signal, since error blocks may never surface |
| **C** | retrieved set empty while findings assert `source_url`s | |
| **D** | any retrieved URL outside `allowed_domains`, or zero retrieved URLs | see §6 — **open ruling** |
| **E** | `stop_reason === 'max_tokens'` | truncated strict-tool input parses as valid JSON but is not the whole payload |

Separately, **per-finding**: `source_url` not in the retrieved set → that finding
is **QUARANTINED** (row disposition, not a run failure). Quarantined rows are
stored for audit and excluded from retrieval.

`emit_findings` called more than once → **union, log anomaly, no error**.

## 6. Gate D and the `web_fetch` domain escape — OPEN DECISION

**`allowed_domains` is not strictly honored, and `web_fetch` is the vector.**

Measured across 18 key-runs (2 runs × 9 keys):

- 6 distinct foreign URLs total; **3 of them appear in BOTH `aetna`/run1 and
  `umr`/run2** — identical arXiv/medRxiv/NCBI documents under unrelated payer
  scopes. A fixed recurring set, not the model wandering.
- `umr` run 2: `via {search: 97, fetch: 5}` with **exactly 5 foreign URLs — every
  single fetch escaped** `allowed_domains: ["umr.com"]`.
- `aetna` run 1 had 4 foreign; `aetna` run 2 had **0**. **Intermittent**, ~11% of
  key-runs.
- In neither case did any finding actually cite a foreign URL.

**This is why Gate D must be a hard gate and not a warning:** those URLs land in
the retrieved set, so a finding citing the arXiv preprint as Aetna policy would
pass the `source_url` provenance check cleanly.

**Alec's gate-5 ruling was fail-closed** (any foreign URL → run FAILED, no
threshold). **Recommendation pending his decision:** switch to **per-URL
exclusion** — drop foreign URLs from the retrieved set (the provenance gate then
auto-quarantines anything citing them), let the run pass on its legitimate URLs,
and keep a loud `GATE D VIOLATION` line plus a `domain_escape_count` on the run
row. Rationale: failing the whole run discards ~97 good URLs' research over an
intermittent upstream quirk that never reached a payload. **Do not change this
without Alec's word.**

## 7. Migration 025 — decisions and the evidence behind them

`SQL Schemas/025_payer_policy_intel.sql` + `_rollback.sql`. **On `main`, NOT
APPLIED.** Veris plane. Next free Veris number is now **026**.

> Numbering trap: an earlier recon in this feature's history reported "next free =
> 023" and was **wrong** — 023/024 were already taken on `staging`. Enumerate
> across **all refs plus the working tree**, and note `veris-data-notes.md`
> was itself stale on this. As of now the ledger and
> `.claude/rules/sql-migrations.md` both correctly say 026.

Three tables in a **new `intel` schema**: `payer_policy_finding`,
`payer_policy_run`, `payer_policy_run_check`.

**Why `intel` and not `ref`:** `ref`'s 13 tables share a verified
owner-only / no-writer / `SELECT USING(true)` invariant set deliberately in
migration 015. This feature needs a writer, and adding the first writer to `ref`
would erode that invariant permanently. A new schema is cheaper.

**Why not `staging`:** that is the PHI/tenant RLS regime; this data is
tenant-agnostic.

Key design points, each with its measurement:

- **`finding_hash` UNIQUE stays as authored** (`payer_plan|change_type|
  date_effective|source_url`). A redesign was proposed mid-session and
  **retracted** — see §8.
- **`confidence` and `status` are ORTHOGONAL, never collapse them.**
  `confidence` = did the *model* verify the *claim*. `status` = did *our pipeline*
  verify the *source*. In batch 1, 7/10 were `needs_verification` and every one was
  an incomplete retrieval, not doubt.
- **`source_tier` is DERIVED at ingest**, not model-emitted — under a primary-only
  domain map a model-emitted tier is a tautology (10/10 `primary`).
- **`scope` is kept, defaulted `'unclear'`, deliberately unindexed.** It looked
  dead in batch 1 (9/10 `unclear`) but **`web_fetch` brought it alive**: run 2 gave
  `in_network` 1, `out_of_network` 2, `both` 8, `unclear` 1 — zero unused values.
  It is now the most OON-relevant working field.
- **`embedding` is nullable `extensions.halfvec(1024)`**, HNSW
  `halfvec_cosine_ops` m=16 ef_construction=64 — matching
  `staging.claim_signatures` and `ref.carc_embeddings`. **BGE-M3
  (`src/brain2`, `src/brain3`) is the ONE embedding path in this repo and has
  never produced a production row** (all embedding tables are empty). The worker
  writes findings unembedded; a separate BGE-M3 pass fills this. **Do not add a
  second embedding path or a second dim.**
- **A generated `embed_tsv` tsvector + GIN index is the day-one retrieval path**,
  precisely because embeddings may never arrive.
- **`run_check.reason_code` is typed** (`login_gated`, `pdf_not_parsed`,
  `content_not_retrieved`, `budget_exhausted`, `not_published`, `other`) because
  free text made a retryable tuning defect indistinguishable from a permanent
  wall. This paid off immediately — see §9.
- **`no_change` and `unreachable` live ONLY in `payer_policy_run_check`**, never in
  `payer_policy_finding`, never embedded. The finding table has no column able to
  express them; that is the structural guarantee.
- `intel_writer` gets **INSERT + UPDATE only**. No DELETE grant *and* no DELETE
  policy, so the restriction survives a mistaken grant.
- RLS mirrors 015 (`FOR SELECT USING(true)`) **plus** explicit writer INSERT/UPDATE
  policies that 015 does not have — necessary because a non-owner writer is
  otherwise blocked by RLS.
- `cost_usd` is `numeric(12,4)`, a **deliberate deviation** from the
  `numeric(12,2)` money convention: it is an observability metric, and 4dp stops a
  cheaper model's per-run cost rounding to zero.

## 8. Idempotency — the finding that matters most, and a retraction

**Finding-level idempotency is NOT achievable by hashing. Do not try again.**

Two runs over the **identical** window produced 26 findings then 12, with only
**0–2 overlapping under any candidate key**. The model does not repeat itself — it
extracts *different slices of the same source documents* each run.

Measured on run 1's 26 real findings:

| candidate key | cross-run repeats caught | **within-run false merges** |
|---|---|---|
| current (`payer_plan\|change_type\|date_effective\|url`) | 0/12 | **0 of 26** |
| "stable" (`payer_key\|change_type\|date_published\|url`) | 1/12 | **10 of 26** |
| doc-level (`payer_key\|date_published\|url`) | 2/12 | **16 of 26** |

**A redesign was proposed on one key's data and retracted once all nine were in.**
Every "more stable" key destroys 10–16 of 26 findings by collapsing distinct ones.
The current key never false-merges. **025 as authored is correct.**

The specific drift that triggered the false alarm: the same underlying finding
(identical `change_type`, `originator`, all three dates, `scope`, `confidence`,
`source_url`) hashed differently because `payer_plan` is free-form prose the model
rephrased — `"…CY2027 proposed rule"` → `"…CY2027 proposed rule — adaptive b…"`.

**The real reducer is `PRIOR STATE`, which suppressed 54%** (26 → 12). Near-
duplicate accumulation over months is inherent and needs a semantic merge pass
(embedding similarity on `embed_text`, or an LLM merge), **not** a constraint.

Note on the earlier "10/10 distinct, zero collisions" claim: that proved
**within-batch distinctness** (no false merges), which is a different property from
**cross-run stability** (no false splits). Don't conflate them again.

## 10. Traps that have already bitten — do not repeat

1. **`git commit` commits the whole INDEX.** A concurrent session had files staged;
   my commit swallowed four of theirs, and after a `git reset --soft` *their* next
   commit swallowed three of mine into `fc2c8f6` ("024 APPLIED LIVE"). **Always
   `git commit -o <paths>`.** Nothing was lost; attribution is muddled. **Do not
   rewrite that history** while another session may be writing to the branch.
2. **`scripts/` was not typechecked.** A `ReferenceError` passed all five
   verification gates because root `tsconfig.json` included only `src/` + `test/`.
   Commit `7985f73` (unpushed) adds `scripts/**/*.ts` — clean, zero errors — and
   this matters because **`scripts/run_payer_intel.ts` is the production GH Actions
   entry point**.
3. **Trailing-dot FQDNs.** `new URL().hostname` preserves the DNS root label, so
   `www.uhcprovider.com.` compared unequal to `uhcprovider.com` and marked a
   healthy run FAILED. Fixed in the module (`9094793`); the probe's private copy on
   `main` still has it (fixed in unpushed `022c40b`). Against an allow-list this
   fails *closed*; the same gap against a block-list is a filter-bypass vector.
4. **Never edit the probe mid-batch.** The roster loop re-invokes
   `scripts/payer_intel_probe.ts` per key, so a mid-flight edit makes later keys
   run different code than earlier ones.
5. **A guard assertion that greps for an identifier will match its own call site.**
   That is how a deleted function passed a "did I delete it?" check.
6. **Same-day re-runs prove nothing about suppression.** `priorStateBlock` excludes
   the current date stamp, so a re-run on the same `RUN_DATE` sees an empty
   `PRIOR STATE`. Re-stamp the previous artifacts to an earlier date first.
7. **`timeout` is not available on macOS** by default; use a background PID + `kill`.
